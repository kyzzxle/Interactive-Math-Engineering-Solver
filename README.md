# Interactive Math & Engineering Solver Hub

A static educational website of step-by-step math and engineering calculators.
Plain HTML + Tailwind CSS (CDN) + vanilla JavaScript; formulas are rendered to MathML
with a self-hosted copy of KaTeX. 58 calculators across 9 subjects, many with interactive explorers and practice problems.
No backend, no database, no framework — it runs on GitHub Pages.

## 1. Quick start

You need [Node.js](https://nodejs.org) 22 or newer (only for the build/preview/test tools — the website itself needs nothing).

```bash
npm run serve      # preview at http://localhost:8080
npm run build      # apply site.config.json and regenerate shared parts of every page
npm test           # math tests, SEO checks and broken-link check
```

There is nothing to install: the tools use only Node's built-in modules.

```
│       ├── site-config.js          ← generated from site.config.json

│       ├── lib/                    Shared, tested helpers: parsing, formatting, exact
│       │                           fractions/radicals, BigInt, an expression engine
│       │                           (parse, simplify, differentiate, integrate),
│       │                           numerical methods, matrices, graphs, diagrams, UI
│       ├── calculators/            Pure math for each calculator (no DOM)
│       ├── explore/                "Explore" and "Try it" specs (no DOM): solids, geometry,
│       │                           functions (algebra/trig/calculus), data, physics
│       ├── pages/                  Page scripts (source, ES modules)
│       └── bundles/                ← generated: one plain script per page, so pages
│                                     also work when opened straight from disk
├── tools/

│   ├── serve.mjs                   Local preview server that mimics GitHub Pages
│   ├── check-links.mjs             Broken-link checker
│   ├── page-template.mjs           Builds generated calculator pages
│   ├── katex-node.mjs              Renders TeX to MathML at build time
│   └── partials/                   Shared <head>, header and footer templates
├── tests/                          Automated tests (node --test)
└── .github/workflows/deploy.yml    Automatic build, test and deploy
```

**How shared parts work:** every page contains markers such as
`<!-- build:header --> … <!-- /build:header -->`. Running `npm run build` refills
everything between the markers from `tools/partials/` and `data/calculators.json`,
so the header, footer, calculator cards, structured data (JSON-LD), sitemap and
robots.txt are always consistent. Never edit inside the markers by hand — edit the
partial or the data file and rebuild. Everything outside the markers is normal HTML.

**How formulas work:** write TeX in page text as `\( … \)` (inline) or `\[ … \]`
(display). The build converts each one into MathML, which every modern browser draws
natively — so visitors never see raw TeX, even without JavaScript or when a page is
opened straight from disk. The original TeX is kept in a `data-tex` attribute, so
rebuilding is safe. Inside TeX in HTML files, write `<` and `>` as `&lt;` and `&gt;`.
Results created in the browser are rendered the same way by `math-render.js`; if that
ever fails, a readable plain-text version is shown instead.

## 3. Configuration (`site.config.json`)

| Setting | What to put there |
|---|---|
| `siteUrl` | Full address of the live site, no trailing slash. Example: `https://yourname.github.io/your-repo`. Leave empty to let GitHub Actions fill in the GitHub Pages address automatically. |
| `customDomain` | Your domain once it is connected, e.g. `www.yourdomain.com`. When set, it becomes the site URL (canonical links, sitemap) and a `CNAME` file is generated. |
| `contact.formEndpoint` | Optional. An HTTPS form endpoint (for example a free [Formspree](https://formspree.io) form URL). Messages from the contact page are sent there. |
| `contact.email` | Optional. A public contact address. Used as a fallback (opens the visitor's email app) and shown on the contact page. Use an address you are happy to publish. |
| `adsense.enabled` | `false` until AdSense approves your site. |
| `adsense.publisherId` | Your ID from AdSense, format `ca-pub-` + 16 digits. |
| `adsense.mode` | `"manual"` (fills the reserved ad slots) or `"auto"` (lets AdSense Auto ads choose placements). |
| `adsense.slots` | Ad-unit IDs (10 digits) for `header`, `afterCalculator`, `inArticle`, `bottom`. Slots left empty stay hidden. |
| `adsense.showPlaceholders` | `true` shows dashed boxes where ads will appear (for layout checks). You can also add `?ads=preview` to any URL. |

After changing this file, run `npm run build` (or just push — the GitHub Action builds for you).

> ⚠️ Until `siteUrl` or `customDomain` is set **or** the site is deployed through the included GitHub Action, the pages contain the placeholder address `https://your-username.github.io/your-repository`. The build prints a warning while that is the case.

## 4. Deploying to GitHub Pages

**Recommended: automatic deployment with GitHub Actions** (already set up in `.github/workflows/deploy.yml`).

1. Create a new repository on GitHub (public, or private if your plan supports Pages for private repos).
2. Upload this folder to it. With Git:
   ```bash
   git init
   git add .
   git commit -m "Initial website"
   git branch -M main
   git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
   git push -u origin main
   ```
3. On GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Open the **Actions** tab. The "Deploy to GitHub Pages" workflow builds the site, runs all tests and publishes it. It runs again on every push to `main`.
5. Your site appears at `https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/`. The workflow automatically uses that address for canonical links and the sitemap while `siteUrl` and `customDomain` are empty.

**Alternative: deploy from a branch** (no Actions). Set `siteUrl` in `site.config.json`, run `npm run build`, commit, then choose **Settings → Pages → Source: Deploy from a branch → main / (root)**. In this mode you must rebuild and commit every time you change the config.

## 5. Connecting your custom domain

Do this after the site works at its github.io address.

1. **Tell GitHub the domain:** Settings → Pages → Custom domain → enter e.g. `www.yourdomain.com` → Save.
2. **Add DNS records** at your domain provider (wherever you activated the domain from the GitHub Student Developer Pack):
   - For `www.yourdomain.com`: a **CNAME** record, host `www`, value `YOUR-USERNAME.github.io`
   - For the bare domain `yourdomain.com`: four **A** records pointing to
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
     (and optionally **AAAA** records `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`).
   Always double-check these values against GitHub's current guide: <https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site>.
3. **Verify the domain** in your GitHub account settings (Settings → Pages → Add a verified domain). This prevents anyone else from taking it over.
4. Wait for DNS to update (minutes to 24 hours), then tick **Enforce HTTPS**.
5. **Update the site config:** set `"customDomain": "www.yourdomain.com"` in `site.config.json` and push. The build switches every canonical URL, the sitemap and robots.txt to your domain, and writes a `CNAME` file.
   - With GitHub Actions deployment the `CNAME` file is not required (GitHub uses the Settings value) but it does no harm.
   - With branch deployment the generated `CNAME` file is what GitHub reads.
6. Submit `https://www.yourdomain.com/sitemap.xml` in [Google Search Console](https://search.google.com/search-console).

`CNAME.example` only shows the format of that file; it is never used.

## 6. Connecting Google AdSense

AdSense approval is decided by Google and is not guaranteed. AdSense generally expects a site on a domain you control with `ads.txt` at the domain root, so connect your custom domain first.

**Before applying**
1. Make sure the contact page works (set `contact.formEndpoint` or `contact.email`).
2. Personalise `about.html` if you want to add your name or field of study (only facts you are comfortable publishing).
3. Have your own lawyer or school advisor review the privacy policy, terms and disclaimer if possible — templates are not a guarantee of legal compliance.

**Apply and verify ownership**
1. Sign up at <https://adsense.google.com> and add your site.
2. Copy your publisher ID (`ca-pub-XXXXXXXXXXXXXXXX`) into `adsense.publisherId`. Keep `enabled: false` for now.
3. Push. The build adds the `<meta name="google-adsense-account">` verification tag to every page and writes `ads.txt` with:
   `google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0`
   (If AdSense shows a different line under **Sites → ads.txt**, edit the line in `tools/build.mjs` to match exactly.)
4. In AdSense, choose the meta-tag or ads.txt verification method and request a review.

**Privacy messaging (do this before enabling ads)**
- AdSense → **Privacy & messaging** → create a **European regulations (GDPR)** message using Google's certified consent platform, and a **US state regulations** message. The privacy policy already describes these choices, and the footer shows a "Privacy choices" link once ads are enabled.

**After approval**
1. AdSense → **Ads → By ad unit** → create *Display* units (for `header`, `afterCalculator`, `bottom`) and an *In-article* unit (for `inArticle`). Copy each `data-ad-slot` number into `adsense.slots`.
2. Set `"enabled": true` and push.
   Or use **Auto ads**: set `"mode": "auto"`, enable Auto ads in AdSense, and leave `slots` empty.
3. Check pages with `?ads=preview` any time to see where the reserved slots are.

Ad placement design: at most four slots per calculator page — below the header, after the calculator, inside the article, and near the end. Slots are outside every form and button area, take no space until active, and reserve a fixed height once active to avoid layout shift.

## 9. Adding a new calculator

**Recommended: a generated page.** Most calculators need only two files.

1. **Calculator module** — create `assets/js/calculators/<id>.js` exporting
   `calculator = { fields, examples, formula, solve }`. `fields` describes the form
   (labels, units, hints, `showWhen` for conditional fields); `examples` are the worked
   examples (mark one that is meant to fail with `expectError: true`); `solve(values)`
   returns `{ ok: false, errors: [{ field, message }] }` or `{ ok: true, final, answers,
   steps, visual, notes, tables }`. Copy an existing module such as `sphere.js` and use
   the helpers in `lib/calc-kit.js` (`validator`, `fmt`, `tx`, `isExact`).
2. **Article** — create `content/calculators/<id>.html` with the sections `about`,
   `formula`, `example` and `assumptions` (copy an existing file).
3. **Registry** — add an entry to `data/calculators.json` with `"generated": true`, the
   title, description, category, keywords and `related` ids.
4. Run `npm run build` and `npm test`. The generic tests automatically solve every worked
   example, check that every formula renders, and fuzz every field with invalid input.

**Optional: an explorer and a practice problem.** Add `explore` and/or `practice` to the
calculator object and the page gets an "Explore and practise" section automatically.

- `explore` — `{ title, intro, controls, presets?, drag?, rotate?, animate?, render(values) }`.
  Each numeric control becomes a slider paired with a number box; `render` returns
  `{ svg, html?, readouts: [{ label, tex | text, tone? }], note? }`. Points drawn with
  `plot({ points: [{ drag: 'A' }] })` can be dragged; `animate: { control: 't' }` adds Play,
  Pause and Reset (never autoplays; the slider is the non-animated alternative).
- `practice` — `{ title, generate(rand) }` returning a prompt, answers (`{ label, value,
  decimals?, int?, unit? }`), a hint and worked `steps`. The page adds Check, Hint, Show
  solution and New problem.
- Put specs in `assets/js/explore/` (see the existing files). `tests/learn.test.mjs`
  renders every explorer at its defaults, presets and slider limits and generates 60
  practice problems per calculator, checking for NaN and invalid TeX.

Use these selectively: a simple calculator should stay simple.

**Alternative: a hand-written page** (like the three original calculators):

1. **Math module** — create `assets/js/calculators/<name>.js` exporting a `solve…(input)` function that takes the raw input strings and returns `{ ok: false, errors: [{ field, message }] }` or `{ ok: true, values, steps, notes }`. Reuse `lib/parse.js` (strict parsing), `lib/format.js`, `lib/exact.js` and `lib/bigint.js`. Keep it free of DOM code so it can be tested.
2. **Tests** — add `tests/<name>.test.mjs` that checks results against an independent method (a different formula, a brute-force count, a known textbook answer), plus boundary and invalid inputs.
3. **Page** — copy one of the folders in `calculators/`, rename it to a descriptive slug, and update: `<title>`, meta description, canonical and `og:` URLs, breadcrumbs, `<h1>`, the form fields, and the article. Keep the 13 lesson sections (introduction, purpose, concept, formulas, variables, derivation, worked example, step-by-step example, applications, mistakes, FAQ, related, further learning). FAQ structured data is generated automatically from the visible FAQ.
4. **Page script** — copy a file from `assets/js/pages/` and connect your form to your math module using the helpers in `lib/ui.js` (`wireCalculator`, `resultCard`, `stepsBlock`…).
5. **Registry** — add an entry to `data/calculators.json` (id, name, category, url, summary, keywords, updated). It then appears on the homepage, in the directory, in search and in the footer.
6. Run `npm run build` and `npm test`, preview with `npm run serve`, then push.

Do not publish empty "coming soon" pages: add a calculator to the registry only when it is complete and tested.

## 10. Testing

`npm test` runs:

- **Calculator math** (`tests/frustum`, `point-line`, `combinatorics`, `lib`): textbook examples, comparison with independent formulas (difference of two cones, closest-point parametrisation, Pascal's triangle and naive factorials), exact symbolic forms, special cases (cone, cylinder, point on the line, r = 0, r = n), huge numbers, and invalid inputs.
- **Library tests** (`tests/lib.test.mjs`): parsing, formatting and exact arithmetic helpers.
- **Learning widgets** (`tests/learn.test.mjs`): every explorer and practice generator, plus answer checking (fractions, rounding tolerance, "close" answers).
- **Physics** (`tests/physics.test.mjs`): textbook answers, and all ten "three known, two unknown" kinematics combinations checked against an independently simulated motion.
- **Every generated calculator** (`tests/calculators-generic.test.mjs`): each worked example solves, has a step-by-step solution and renders without TeX errors; no output ever contains `NaN`, `Infinity`, `undefined` or `[object Object]`; every field is fuzzed with about 20 invalid or extreme inputs (empty, text, `1/0`, `1e400`, `1e-300`, …) and must give a helpful error or a clean result.
- **Site checks** (`tests/site.test.mjs`): all 65 indexable pages have required files, unique titles and descriptions, one `<h1>`, no skipped heading levels, valid JSON-LD, the required lesson sections, and no raw TeX in visible text; sitemap matches canonicals, robots.txt, 404 is `noindex`, no ad code without a publisher ID, and generated files up to date.
- **Link check** (`tools/check-links.mjs`): every internal link, asset and `#anchor`.

The GitHub Action runs the same tests before every deployment and stops if any fail.

## 11. Technical decisions

- **Static pages with a small build step.** Every calculator is a real, crawlable HTML page. A zero-dependency Node script keeps shared parts consistent without a framework. The committed files always work as-is.
- **Relative links everywhere** (`./`, `../../`), so the site works both at `username.github.io/repo/` and at the root of a custom domain. The 404 page uses a `<base>` tag written by the build because GitHub Pages serves it at any depth.
- **Math separated from UI.** Pure math modules are unit-tested in Node; page scripts only handle the DOM.
- **Exact arithmetic where it matters.** Integer and short-decimal inputs are scaled to integers so answers can be shown in simplest radical form and as multiples of π (e.g. `(34 + 16√5)π`). Counting uses BigInt with binary-splitting multiplication; results beyond 200,000 digits switch to a Stirling/log-based approximation that is clearly labelled.
- **Honest labels.** Every result says whether it is exact or a rounded approximation; π multiples are always marked approximate.
- **MathML rendered at build time.** KaTeX 0.16.11 (self-hosted in `assets/vendor/katex/`) converts TeX to MathML, which browsers draw natively with no fonts or stylesheet. Static formulas are converted by the build; formulas in results are converted in the browser.
- **Bundled page scripts.** ES-module sources are bundled into plain scripts in `assets/js/bundles/`, because browsers block module scripts on `file://` pages.
- **One shared calculator controller.** Generated pages use `pages/calculator-page.js`, which handles validation messages, live recalculation, worked examples, show/hide steps, copying and shareable URLs the same way on every page.
- **Tailwind compiled ahead of time** (v3.4.16, `npm run css`) into `assets/css/tailwind.css` (about 10 KB), loaded after `styles.css` so utilities win exactly as they did with the old CDN. No JavaScript is needed for styling.
- **Link previews.** `npm run og` renders a 1200×630 card per calculator into `assets/og/` with headless Chrome or Edge; the build adds `og:image` and `twitter:image` tags (falling back to `default.jpg`).
- **Homepage demo.** `pages/home-page.js` mounts small text-only explorers from `explore/home.js`, so the homepage still doesn't load KaTeX.
- **Shareable results.** Inputs are stored in the URL query (`?r=6&R=9…`); canonical links always point to the clean URL, so this creates no duplicate pages for search engines.
- **Learning widgets without libraries.** Explorers redraw a small SVG on each change (2D graphs with `lib/plot.js`, rotatable solids with `lib/solid3d.js`, which draws only the faces that point towards the viewer). Animations run only after the visitor presses Play and pause when the tab is hidden.
- **Privacy by design.** No analytics, no cookies of our own; only a `theme` value in localStorage.

## 12. Known limitations and future improvements

**Limitations**
- MathML needs a current browser (Chrome/Edge 109+, Firefox, Safari). Very old browsers show formulas with simpler spacing.
- After editing formulas in a page or content file, run `npm run build` — the static formulas are converted by the build.
- AdSense, the contact-form endpoint, custom-domain DNS and the GitHub Actions run need your accounts and were not tested live.
- After adding a calculator or using new Tailwind classes, run `npm run og` (needs Chrome or Edge) and `npm run css` (downloads the Tailwind CLI once via npx), then commit the generated files.

**Deliberate limits of the calculators** (each page states its own limits too)
- *Trig identity checker* tests an identity numerically at many points; it does not produce an algebraic proof.
- *Indefinite integrals* use a table of rules (polynomials, xⁿ, 1/x, (ax + b)ⁿ, exponentials, the six trig functions, sec², csc², sinh, cosh, and sums and constant multiples of these). Integrals that need parts, partial fractions or trig substitution are reported as unsupported rather than guessed.
- *Critical points* work for polynomials of degree 2 to 6 only.
- *Polynomial factoring* works over the rationals for degrees 2 to 6; factors that are irreducible over the rationals are left as they are.
- *Trig equation solver* handles equations of the form a·f(bx + c) + d = k.
- *Confidence intervals* use summary statistics; the proportion interval is the Wald interval and requires at least 10 successes and 10 failures.
- *Physics calculators* use SI units and simplified models, stated on each page: constant velocity or acceleration along a line, no air resistance for projectiles and falls, constant g, ohmic resistors and ideal wires. Resistor networks support series, parallel, and parallel branches of series resistors (no bridges).
- *Logarithm calculator* evaluates logarithms and solves two equation types: log_b(ax + c) = d and b^(ax + c) = k. The *exponent simplifier* has three modes: exponent laws, radicals, and numeric powers.

**Recommended improvements**
1. Add a PNG `apple-touch-icon` for phones' home screens.
2. Extend the generated pages with FAQ and common-mistakes sections like the three original pages.
3. Add explorers or practice problems to more calculators (for example the three hand-written pages), and printable practice sets.
4. Add privacy-friendly analytics only if you need it — and update the privacy policy first.
